# רובוט מסחר מבוסס מגמות (מסחר וירטואלי)

רובוט שסורק את מניות **נאסד"ק** (נאסד"ק‑100 או כל המניות הרשומות) או את **ת"א‑35**, מזהה מניות במגמת עלייה, ומבצע קניות ומכירות **וירטואליות** על נתוני שוק עדכניים. בנוסף הוא משפר את הפרמטרים של עצמו כל עוד הממוצע החודשי נמוך מהיעד (ברירת מחדל: 10%).

## התקנה
```bash
pip install -r requirements.txt
```

## שימוש
```bash
# 1. סריקה: אילו מניות נמצאות כרגע במגמת עלייה
python -m trading_bot scan --market nasdaq100
python -m trading_bot scan --market ta35

# 2. בדיקה היסטורית (backtest) על 5 שנים
python -m trading_bot backtest --market nasdaq100

# 3. שיפור עצמי: חיפוש פרמטרים טובים יותר
python -m trading_bot optimize --market nasdaq100            # עד 300 ניסיונות
python -m trading_bot optimize --market nasdaq100 --forever --max-hours 8   # רץ עד שמגיע ליעד או עד שנגמר הזמן

# 4. מסחר וירטואלי על נתוני זמן אמת (בדיקה כל 15 דקות + אופטימיזציה מחדש כל 7 ימים)
python -m trading_bot paper --market nasdaq100 --interval 15

# 5. מצב התיק הווירטואלי
python -m trading_bot status
```
השוקים הנתמכים: `nasdaq100`, `nasdaq_all` (כל נאסד"ק, אחרי סינון מניות לא נזילות), `ta35`.
אפשר גם להשתמש ברשימה משלך: `--symbols-file my_list.txt`.
להרצה בלי אינטרנט, על נתונים מדומים, מוסיפים `--synthetic` (רק לבדיקת התוכנה).

## האסטרטגיה
| שלב | כלל |
|---|---|
| כניסה | EMA מהיר > EMA איטי, המחיר מעל ה‑EMA האיטי, ADX ≥ סף, ‎+DI > ‎‑DI, מומנטום חיובי, ורוחב שוק מספיק (אחוז המניות במגמת עלייה) |
| דירוג | המועמדות מדורגות לפי מומנטום מותאם תנודתיות, והטובות ביותר נכנסות לתיק |
| גודל פוזיציה | הנמוך מבין: הון חלקי מספר הפוזיציות המרבי, או סיכון של 1% מההון אם הסטופ נפגע |
| יציאה | Trailing stop לפי ATR, או חציה של ה‑EMA המהיר אל מתחת לאיטי |
| עלויות | עמלה של 0.1% ו‑slippage של 0.05% בכל צד |

האות מחושב על סגירת יום t והביצוע מתבצע ביום t+1, כך שאין שימוש במידע מהעתיד (יש על זה בדיקה אוטומטית). המנוע שמריץ את הבדיקה ההיסטורית הוא אותו מנוע שמריץ את המסחר הווירטואלי.

## איך עובד השיפור העצמי
1. **הפרדת תקופות**: 12 החודשים האחרונים (holdout) לא משמשים לבחירת פרמטרים, אלא רק למדידה כנה של הביצועים על נתונים שהמודל לא ראה.
2. **ציון חסין**: כל ניסיון נמדד על 4 תקופות נפרדות. חוסר עקביות בין התקופות, ירידת ערך (drawdown) מעל 20%, ופחות מ‑30 עסקאות מורידים את הציון.
3. **חיפוש**: בערך 30% מהניסיונות הם חקירה אקראית של פרמטרים חדשים, וכ‑70% הם שינויים קטנים סביב הפרמטרים הטובים ביותר שנמצאו עד כה.
4. **בזמן מסחר וירטואלי**: כל 7 ימים הרובוט בודק את הממוצע החודשי בפועל. אם הוא נמוך מהיעד, הרובוט מריץ אופטימיזציה מחדש על הנתונים העדכניים.

התוצאה נשמרת ב‑`bot_state/champion.json`, כולל הביצועים בתקופת הפיתוח, הביצועים בתקופת ה‑holdout, והשדה `target_met_out_of_sample`.

## ⚠️ חשוב לדעת על יעד ה‑10% בחודש
* 10% בחודש הם בערך **214% בשנה**. גם קרנות הגידור הטובות בעולם לא מגיעות לזה לאורך זמן. אסטרטגיה מוצלחת מאוד לטווח ארוך מגיעה בדרך כלל ל‑1% עד 2% בחודש בממוצע, עם חודשים שליליים.
* אופטימיזציה שלא עוצרת עד שמגיעים ל‑10% תמצא בסוף פרמטרים ש"משננים" את העבר (overfitting): הם ייראו מצוין בבדיקה ההיסטורית ויפסידו בשוק האמיתי. לכן הרובוט מחשב את היעד רק על תקופת ה‑holdout שהוא לא ראה, ומציג את התוצאה בשקיפות. ההבדל בין התוצאות בתקופת הפיתוח לתוצאות ב‑holdout הוא המדד החשוב ביותר.
* אין רובוט שמרוויח בכל תקופה. אסטרטגיית מגמה מפסידה בשווקים "מדשדשים" (בלי מגמה ברורה), ובשביל זה יש מסנן רוחב שוק וסטופים.
* מומלץ להריץ מסחר וירטואלי לפחות 3 עד 6 חודשים לפני ששוקלים כסף אמיתי.

## נתונים
* מקור הנתונים הוא Yahoo Finance (`yfinance`). למניות בארה"ב המחירים כמעט בזמן אמת, ובתל אביב יש עיכוב. לנתוני זמן אמת מלאים אפשר להחליף את `data.live_prices` ב‑API של ברוקר (למשל Interactive Brokers או Alpaca).
* רשימות המדדים ב‑`universe.py` הן תמונת מצב, וצריך לעדכן אותן מדי פעם. במצב `nasdaq_all` הרשימה נמשכת אוטומטית מאתר NASDAQ.

| `optimizer.py` | לולאת השיפור העצמי |
| `paper_trader.py` | מסחר וירטואלי חי |
